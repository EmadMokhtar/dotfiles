# Secrets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `secret` command that gives secrets to a program, or to a macOS app, only when it starts — from the macOS keychain, 1Password, or a command — and a bootstrap that installs it.

**Architecture:** One bash 3.2 script, `bin/secret`, linked to `~/.local/bin/secret`. A map file outside the repo (`~/.config/secrets/secrets.map`) lists each secret name and its source, and which secrets each app gets. OS-specific code sits in a few `os_*` functions so a Linux phase can add a backend later. The existing `claude()` zsh wrapper is rewritten to call `secret run`.

**Tech Stack:** bash 3.2 (`/bin/bash` on macOS), macOS `security` / `plutil` / `pgrep` / `stat`, 1Password CLI `op`, zsh, bats-core (Bash Automated Testing System — a test runner for shell scripts), shellcheck (a linter for shell scripts).

**Spec:** `docs/superpowers/specs/2026-10-11-secrets-design.md` (Task 7 amends it in two places; see Review Focus item 3).

All commands run from the repository root (the worktree `secrets-1password-integration-1cfc42`).

## Global Constraints

- `bin/secret` must run on `/bin/bash` 3.2: no associative arrays, no `mapfile`. It has no `set -e` and no `set -u` (an empty array breaks `set -u` on bash 3.2). It never enables `set -x`.
- Keychain item: service `dotfiles-secrets`, account `NAME`. Write with `security add-generic-password -U -a NAME -s dotfiles-secrets -w` and **no value argument** (`-w` last). Read with `security find-generic-password -a NAME -s dotfiles-secrets -w`.
- 1Password read: `op read --no-newline <reference>`. Command source: `bash -c '<command>'`, output is the value, an empty value is a failure.
- Map: `~/.config/secrets/secrets.map` (file mode 600, directory mode 700). Template: `secrets/secrets.map.example`. Source types: `keychain`, `op://...`, `cmd:...`. The name `app` is reserved.
- Exit codes: `0` success (for `run`, the program's own code), `1` a secret/app/map cannot be resolved, `2` usage error.
- Fail closed by default. `--optional` turns a failed secret into a warning.
- A value is never written to a file, a log, an error message or the argument list of another command. Error messages hold names and reasons only, never values or `op://` references.
- Only macOS now. On any other OS every command stops with `unsupported OS: <name> (macOS only for now)`, exit `1`.
- `bin/secret` is its own process, so exporting values in it and then calling `exec` meets the spec's "subshell, then exec" rule. Task 7 updates the spec wording.
- Tests use the `make_sandbox` and `stub` helpers in `tests/helpers.bash`: a temporary `HOME`, fake `security`, `op`, `pgrep`, `uname`, `stat`. All test values are fake strings. Tests never touch the real keychain, 1Password or `HOME`.
- Commit messages follow Conventional Commits (user rule) and end with the trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Code comments and messages use simple, direct English (user rule).
- Every task ends with `shellcheck` clean and the whole `bats tests/` suite green.

## Review Focus

Inputs and conditions the spec implies but a first implementation easily gets wrong, most likely first. Each has a test in the task that owns the code.

1. A secret value that contains spaces, quotes, `$` and `=` must reach the program unchanged. Test in Task 2: "run keeps spaces, quotes, dollar signs and equals signs in a value".
2. Program arguments after `--` that contain spaces must be passed unchanged. Test in Task 2: "run passes the program's arguments through unchanged".
3. `claude` must still start when the map is missing, unsafe or broken. The spec only said "a name that is not in the map" for `--optional`; without this, a deleted map would stop `claude` from starting at all. Tests in Task 2 (three `--optional` map cases) and Task 6 (`claude` through the real script). Task 7 amends the spec.
4. `secret set` on a map whose last line has no trailing newline must not glue two entries together. Test in Task 3: "set starts a new line when the map does not end with one".
5. `secret open` for an app whose executable name differs from its app name, and whose name contains spaces (like "Visual Studio Code"). Test in Task 4: "open starts the app with its secrets, even when the executable name differs".

Create `bin/secret` with this content, then make it executable with `chmod +x bin/secret`:

```bash
#!/usr/bin/env bash
# secret — give secrets to a program only when it starts.
#
#   secret set NAME
#   secret run [--optional] NAME... -- command [args...]
#   secret open [--optional] APP
#   secret list
#
# Design: docs/superpowers/specs/2026-10-11-secrets-design.md
#
# Must work on bash 3.2, the version macOS ships: no associative arrays, no
# mapfile. `set -e` and `set -u` are off on purpose: an empty array breaks
# `set -u` on bash 3.2, and every failure path below is handled by hand.
# Never turn on `set -x`: it would print secret values.

SERVICE="dotfiles-secrets"
MAP="$HOME/.config/secrets/secrets.map"
OS="$(uname -s)"

# ---- output helpers -------------------------------------------------------

die()         { printf 'secret: %s\n' "$*" >&2; exit 1; }
warn()        { printf 'secret: warning: %s\n' "$*" >&2; }
usage_error() { printf 'secret: %s\n\n' "$1" >&2; usage >&2; exit 2; }

usage() {
  cat <<'EOF'
Usage: secret <command> [options]

  set NAME                            store a value in the keychain (hidden prompt)
  run [--optional] NAME... -- CMD...  run CMD with the named secrets
  open [--optional] APP               start a macOS app with its secrets
  list                                show names and sources, never values

--optional: when a secret cannot be read, warn and continue without it.
The map of names and sources is ~/.config/secrets/secrets.map.
EOF
}

# ---- platform layer: everything that depends on the operating system -------
# Only macOS (Darwin) is supported for now. A Linux phase adds a branch to
# each function. See the design, "Platform layer and Linux".

unsupported_os() { die "unsupported OS: $OS (macOS only for now)"; }

# os_file_owner_mode <path> — print "<uid> <octal mode>", for example "501 600".
os_file_owner_mode() {
  case "$OS" in
    Darwin) stat -f '%u %Lp' "$1" ;;
    *) unsupported_os ;;
  esac
}

# ---- the map ----------------------------------------------------------------

SECRET_NAMES=()
SECRET_SOURCES=()
SECRET_LINES=()
APP_NAMES=()
APP_LISTS=()

NAME_RE='^[A-Za-z_][A-Za-z0-9_]*$'

# valid_name <name> — an environment variable name; "app" is reserved.
valid_name() {
  [[ $1 =~ $NAME_RE ]] && [ "$1" != "app" ]
}

# FALLBACK_CMD is set by `run --optional`. When the map itself is unusable, that
# program still starts, without secrets. In every other case it is fatal.
FALLBACK_CMD=()

# map_die <message> — report a problem with the map file.
map_die() {
  if [ "${#FALLBACK_CMD[@]}" -gt 0 ]; then
    warn "$*; continuing without secrets"
    exec "${FALLBACK_CMD[@]}"
  fi
  die "$*"
}

map_error() { map_die "$MAP line $1: $2"; }

# check_map_safety — the map can hold `cmd:` lines, which run code. Refuse a
# map that another user owns or can write.
check_map_safety() {
  local info owner mode
  info="$(os_file_owner_mode "$MAP")" || map_die "cannot read the owner of $MAP"
  owner="${info% *}"
  mode="${info#* }"
  [ "$owner" = "$(id -u)" ] || map_die "$MAP is not owned by you; refusing to read it"
  if [ $(( 8#$mode & 8#022 )) -ne 0 ]; then
    map_die "$MAP can be written by other users (mode $mode); run: chmod 600 $MAP"
  fi
}

# parse_map — fill SECRET_* and APP_* from the map. Checks the syntax of every
# line and that no secret name appears twice.
parse_map() {
  local lineno=0 line first rest words list appname i item items
  SECRET_NAMES=(); SECRET_SOURCES=(); SECRET_LINES=()
  APP_NAMES=(); APP_LISTS=()
  while IFS= read -r line || [ -n "$line" ]; do
    lineno=$((lineno + 1))
    first=""; rest=""
    read -r first rest <<< "$line"
    case "$first" in "" | "#"*) continue ;; esac

    if [ "$first" = "app" ]; then
      read -r -a words <<< "$rest"
      [ "${#words[@]}" -ge 2 ] ||
        map_error "$lineno" "an app line needs an app name and a list of secret names"
      list="${words[${#words[@]}-1]}"
      appname="${words[0]}"
      for (( i=1; i<${#words[@]}-1; i++ )); do
        appname="$appname ${words[$i]}"
      done
      case "$list" in
        ,* | *, | *,,*) map_error "$lineno" "bad list of secret names: $list" ;;
      esac
      IFS=, read -r -a items <<< "$list"
      for item in "${items[@]}"; do
        valid_name "$item" || map_error "$lineno" "bad secret name in the list: $item"
      done
      APP_NAMES+=("$appname")
      APP_LISTS+=("$list")
      continue
    fi

    valid_name "$first" || map_error "$lineno" "bad secret name: $first"
    case "$rest" in
      keychain | op://?* | cmd:?*) ;;
      *) map_error "$lineno" "bad source for $first (use keychain, op://..., or cmd:...)" ;;
    esac
    for (( i=0; i<${#SECRET_NAMES[@]}; i++ )); do
      if [ "${SECRET_NAMES[$i]}" = "$first" ]; then
        map_die "$MAP: $first is defined twice (lines ${SECRET_LINES[$i]} and $lineno)"
      fi
    done
    SECRET_NAMES+=("$first")
    SECRET_SOURCES+=("$rest")
    SECRET_LINES+=("$lineno")
  done < "$MAP"
}

# secret_index <name> — print the position of <name> in SECRET_NAMES, or fail.
secret_index() {
  local i
  for (( i=0; i<${#SECRET_NAMES[@]}; i++ )); do
    if [ "${SECRET_NAMES[$i]}" = "$1" ]; then
      printf '%s\n' "$i"
      return 0
    fi
  done
  return 1
}

# validate_apps — every name in an app list must have a secret line.
validate_apps() {
  local i item items
  for (( i=0; i<${#APP_NAMES[@]}; i++ )); do
    IFS=, read -r -a items <<< "${APP_LISTS[$i]}"
    for item in "${items[@]}"; do
      secret_index "$item" >/dev/null ||
        map_die "$MAP: app '${APP_NAMES[$i]}' lists $item, which has no secret line"
    done
  done
}

# load_map — read and fully check the map, or stop with a message.
load_map() {
  [ -f "$MAP" ] || map_die "no map at $MAP (copy secrets/secrets.map.example there)"
  check_map_safety
  parse_map
  validate_apps
}

# app_secret_list <app name> — print the comma-separated secret names of an app,
# merged from all of its lines in file order.
app_secret_list() {
  local i list=""
  for (( i=0; i<${#APP_NAMES[@]}; i++ )); do
    if [ "${APP_NAMES[$i]}" = "$1" ]; then
      list="${list:+$list,}${APP_LISTS[$i]}"
    fi
  done
  printf '%s\n' "$list"
}

# ---- commands ---------------------------------------------------------------

cmd_list() {
  local i src done_apps app
  [ $# -eq 0 ] || usage_error "list takes no arguments"
  load_map
  printf '%-32s %s\n' "SECRET" "SOURCE"
  for (( i=0; i<${#SECRET_NAMES[@]}; i++ )); do
    case "${SECRET_SOURCES[$i]}" in
      keychain) src="keychain" ;;
      op://*)   src="1password" ;;
      cmd:*)    src="command" ;;
    esac
    printf '%-32s %s\n' "${SECRET_NAMES[$i]}" "$src"
  done
  printf '\n%-32s %s\n' "APP" "SECRETS"
  done_apps=()
  for (( i=0; i<${#APP_NAMES[@]}; i++ )); do
    app="${APP_NAMES[$i]}"
    if array_has "$app" "${done_apps[@]}"; then
      continue
    fi
    done_apps+=("$app")
    printf '%-32s %s\n' "$app" "$(app_secret_list "$app")"
  done
}

# array_has <needle> <item>... — succeed when <needle> is one of the items.
array_has() {
  local needle="$1" item
  shift
  for item in "$@"; do
    [ "$item" = "$needle" ] && return 0
  done
  return 1
}

# ---- main -------------------------------------------------------------------

main() {
  local cmd="${1:-}"
  case "$cmd" in
    "")                 usage >&2; exit 2 ;;
    -h | --help | help) usage; exit 0 ;;
  esac
  [ "$OS" = "Darwin" ] || unsupported_os
  shift
  case "$cmd" in
    list) cmd_list "$@" ;;
    *)    usage_error "unknown command: $cmd" ;;
  esac
}

main "$@"
```

# ---- resolving values -------------------------------------------------------

RESOLVED_VALUE=""
RESOLVE_ERROR=""
EXPORT_NAMES=()
EXPORT_VALUES=()

# resolve_secret <name> — look the value up. On success sets RESOLVED_VALUE.
# On failure sets RESOLVE_ERROR (a reason, never a value) and returns 1.
resolve_secret() {
  local name="$1" idx src value
  RESOLVED_VALUE=""
  RESOLVE_ERROR=""
  if ! idx="$(secret_index "$name")"; then
    RESOLVE_ERROR="not in the map"
    return 1
  fi
  src="${SECRET_SOURCES[$idx]}"
  case "$src" in
    keychain)
      value="$(os_store_get "$name")" || {
        RESOLVE_ERROR="no readable keychain item (run: secret set $name)"
        return 1
      }
      ;;
    op://*)
      command -v op >/dev/null 2>&1 || {
        RESOLVE_ERROR="the 1Password CLI (op) is not installed"
        return 1
      }
      value="$(op read --no-newline "$src")" || {
        RESOLVE_ERROR="1Password could not read it (is op signed in?)"
        return 1
      }
      ;;
    cmd:*)
      value="$(bash -c "${src#cmd:}")" || {
        RESOLVE_ERROR="the command failed"
        return 1
      }
      ;;
  esac
  if [ -z "$value" ]; then
    RESOLVE_ERROR="the value is empty"
    return 1
  fi
  RESOLVED_VALUE="$value"
}

# collect_secrets <optional 0|1> <name>... — resolve every name into
# EXPORT_NAMES and EXPORT_VALUES. A failure stops the program, or only warns
# when optional is 1.
collect_secrets() {
  local optional="$1" name
  shift
  EXPORT_NAMES=()
  EXPORT_VALUES=()
  for name in "$@"; do
    if resolve_secret "$name"; then
      EXPORT_NAMES+=("$name")
      EXPORT_VALUES+=("$RESOLVED_VALUE")
    elif [ "$optional" = "1" ]; then
      warn "$name: $RESOLVE_ERROR; continuing without it"
    else
      die "cannot resolve $name: $RESOLVE_ERROR"
    fi
  done
  RESOLVED_VALUE=""
}

# export_collected — put the collected values into this process's environment.
export_collected() {
  local i
  for (( i=0; i<${#EXPORT_NAMES[@]}; i++ )); do
    export "${EXPORT_NAMES[$i]}=${EXPORT_VALUES[$i]}"
  done
}

# append_map_line <name> — add "<name> keychain" to the map. Creates the
# directory (mode 700) and the file (mode 600) when they are missing.
append_map_line() {
  local dir
  dir="$(dirname "$MAP")"
  if [ ! -d "$dir" ]; then
    mkdir -p "$dir" || die "cannot create $dir"
    chmod 700 "$dir"
  fi
  if [ ! -e "$MAP" ]; then
    ( umask 077; : > "$MAP" ) || die "cannot create $MAP"
  fi
  # Start a new line when the file does not end with one.
  if [ -s "$MAP" ] && [ -n "$(tail -c 1 "$MAP")" ]; then
    printf '\n' >> "$MAP"
  fi
  printf '%-32s keychain\n' "$1" >> "$MAP"
}

  name="$1"

# darwin_app_bundle <app name> — print the path of <app name>.app, or fail.
darwin_app_bundle() {
  local dir
  for dir in /Applications "$HOME/Applications"; do
    if [ -d "$dir/$1.app" ]; then
      printf '%s\n' "$dir/$1.app"
      return 0
    fi
  done
  return 1
}

# os_app_executable <app name> — print the path of the program inside the app.
os_app_executable() {
  local bundle exe
  case "$OS" in
    Darwin)
      bundle="$(darwin_app_bundle "$1")" ||
        die "app not found: $1 (looked in /Applications and ~/Applications)"
      exe="$(plutil -extract CFBundleExecutable raw -o - "$bundle/Contents/Info.plist" 2>/dev/null)" ||
        die "cannot read the executable name in $bundle/Contents/Info.plist"
      printf '%s\n' "$bundle/Contents/MacOS/$exe"
      ;;
    *) unsupported_os ;;
  esac
}

# os_app_running <app name> — succeed when a process runs from inside the app.
os_app_running() {
  local bundle escaped
  case "$OS" in
    Darwin)
      bundle="$(darwin_app_bundle "$1")" || return 1
      escaped="$(printf '%s' "$bundle" | sed 's/[][\.*^$+?(){}|]/\\&/g')"
      pgrep -f "^$escaped/Contents/" >/dev/null 2>&1
      ;;
    *) unsupported_os ;;
  esac
}

````markdown
## Secrets

`bin/secret` gives secrets to a program only when you start it. Nothing is
exported at shell start and no value is stored in this repo. macOS only for now.

Each secret has a name and one source. They are listed in
`~/.config/secrets/secrets.map`, which is not tracked in git. Bootstrap creates
it from `secrets/secrets.map.example` and never overwrites it.

| Source | Meaning |
|---|---|
| `keychain` | You type the value once with `secret set NAME`. It is kept in the login keychain. |
| `op://Vault/Item/field` | Read from 1Password with `op read`. |
| `cmd:<command>` | The output of a command, for example `cmd:gh auth token`. |

```bash
secret set OPENAI_API_KEY                      # hidden prompt, saved in the keychain
secret run OPENAI_API_KEY -- some-tool --flag  # run one program with the secret
secret open Zed                                # start a macOS app with its secrets
secret list                                    # names and sources, never values
```

An app gets the secrets on its `app` lines in the map. Use commas for several,
or repeat the line:

```
app Zed    OPENAI_API_KEY,ANTHROPIC_API_KEY
app Zed    OLLAMA_API_KEY
```

Rules and limits:

- If a secret cannot be read, nothing starts. `--optional` turns this into a
  warning and the program starts without that secret. `claude` uses it.
- `secret open` stops if the app is already running. Quit it first: a running app
  keeps the environment it started with.
- An app started from the Dock, Spotlight or Login Items gets no secrets. Start
  it with `secret open`.
- The map can run commands (`cmd:` lines), so `secret` refuses to read it when
  another user owns it or can write it. Keep it at mode 600.
- This reduces accidental exposure. It does not protect against other
  programs running as you: they can call `security` too.
````

## Glossary

- **bats**: Bash Automated Testing System, a test runner for shell scripts.
- **shellcheck**: a linter (a tool that finds mistakes in code without running it) for shell scripts.
- **TDD**: test-driven development. Write a failing test first, then the code that makes it pass.
- **Fail closed**: when something goes wrong, refuse to continue instead of continuing with less protection.
- **`exec`**: replaces the current process with another program.
- **Mutation check**: break the code on purpose and confirm that a test fails.
- **Trailer**: a `Key: value` line at the end of a git commit message.
